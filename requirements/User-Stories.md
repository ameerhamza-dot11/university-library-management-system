# User Stories and Acceptance Criteria

## Project Name
University Library Management System

## Introduction
User stories describe the system features from the perspective of people who will use the University Library Management System.

## User Story 1: Student Login
**As a student**, I want to log in to my account so that I can access library services.

**Acceptance Criteria:**
- The student can enter an email and password.
- Valid login details allow access to the dashboard.
- Invalid details display an error message.

## User Story 2: Search Books
**As a student**, I want to search for books so that I can find books easily.

**Acceptance Criteria:**
- The student can search by title, author, or category.
- Matching books appear in the search results.
- A message appears when no books match the search.

## User Story 3: View Book Details
**As a student**, I want to view book details so that I can check book information.

**Acceptance Criteria:**
- The system displays the title, author, category, and availability.
- The student can open a book's details from search results.

## User Story 4: Reserve a Book
**As a student**, I want to reserve a book so that I can request it for borrowing.

**Acceptance Criteria:**
- The student can select a book and submit a reservation.
- The system displays a reservation confirmation.
- The student can view reservation status.

## User Story 5: Borrow a Book
**As a librarian**, I want to issue books to students so that borrowing records remain accurate.

**Acceptance Criteria:**
- The librarian can select a registered member.
- The librarian can select an available book copy.
- The system records the issue date and due date.
- The system confirms successful issuance.

## User Story 6: Return a Book
**As a librarian**, I want to record returned books so that book availability remains updated.

**Acceptance Criteria:**
- The librarian can find the borrowing record.
- The librarian can record the return.
- The system updates the book copy's availability.
- The system identifies overdue returns.

## User Story 7: Manage Books
**As a librarian**, I want to add and update book records so that the library catalogue remains accurate.

**Acceptance Criteria:**
- The librarian can add a book with its required details.
- The librarian can update existing book information.
- The system displays a confirmation after saving changes.

## User Story 8: View Borrowing History
**As a student**, I want to view my borrowing history so that I can track previously borrowed books.

**Acceptance Criteria:**
- The student can open the borrowing history section.
- The system displays borrowed and returned books.
- Each record displays the issue date and due or return date.

## User Story 9: Generate Reports
**As a university administrator**, I want to generate library reports so that I can monitor library activities.

**Acceptance Criteria:**
- Authorized administrators can open the reports section.
- The system displays borrowing and return information.
- The administrator can select a reporting period.

## Conclusion
These user stories describe the main needs of students, librarians, and university administrators. Acceptance criteria help determine whether each feature works as expected.
